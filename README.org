* Overview
Org-roam-organize is an Emacs package for managing a single Org-roam Map of Contents (MOC) file and node references. It provides a minor mode with commands for checking setup, creating managed nodes, creating the MOC file and missing management headlines, syncing MOC entries from Org-roam node tags, checking managed citation references, and syncing citing-node entries.

* 0.8.0 Changes and Migration
This section describes upgrading from 0.7.0 to 0.8.0. The MOC layout changes
incompatibly to one file with registry-managed CUSTOM_ID headlines. Ordinary
capture and citation synchronization retain their existing models.

** Single-file MOC migration
There is no automatic merge, deletion, or destructive migration. Back up notes
and review incoming ID links before changing existing MOC files.

1. Choose one MOC file, preferably the old navigation file, and preserve its file-level ID and external references. Only the unique =:moc t= record may now declare =:moc-path= or =:moc-id=. Remove =:moc-path= from other records. Optionally set the MOC record's =:moc-id= to the preserved ID; UUIDs of any version and existing link-safe custom Org IDs are accepted.
2. The MOC record must explicitly declare =:template ((keywords . ((filetags . ("map")))))=, substituting its actual =:tag=. It must not write an =ID= property in the template; capture owns the file ID.
3. Move each old record MOC's member entries into a headline in the chosen file with =CUSTOM_ID= equal to that record's =:tag=. The headline title must match =:moc-title= or the capitalized =:name=. Keep all management headlines at the same level (default 1); different parents are allowed. The MOC record has no management headline or member index of its own. Preserve =:delete t= markers, manual order and handwritten contents.
4. Old per-record MOC files may all carry the MOC tag because they used the same MOC template. Remove that tag from extra files and refresh the Org-roam DB before running MOC commands. Multiple tagged file nodes are an error; the package never silently chooses the first match. Keep one uniquely tagged level-0 MOC node.
5. The =MOC_MANAGED_TAG= and =MOC_MANAGED_NODE_COUNT= properties and their two configuration variables are no longer maintained. Review and clean old properties manually, accounting for any custom property names. The former capture info key =:moc_managed_tag= is also removed; update templates that referenced =${moc_managed_tag}=.
6. Each old MOC file had its own node ID. Deleting it can break incoming links. Convert those links deliberately or retain the old file as an archive without the MOC tag. A region's =CUSTOM_ID= is not an Org-roam node ID and does not preserve links to old file IDs.
7. Run =org-roam-organize-moc-create= to add missing structure, then =org-roam-organize-moc-sync= to reconcile member entries. Sync reports missing management regions and does not create them. Configuration/identity/structure conflicts are reported before edits.

** Citation integration changes
- Managed bibliography integration is enabled explicitly with =:bibliography t= on the unique =:cite t= record. Interactive discovery includes all managed literature bibliographies; export adds only those required by managed UUID citations in the effective export tree. Missing or nil =:bibliography= leaves bibliography handling to ordinary Org Cite configuration while UUID-to-citekey conversion remains enabled. Native Org Cite processors own citation and bibliography rendering; the package does not select a processor, repair backend output, or insert =#+print_bibliography:=.
- Managed literature UUID citation keys are displayed as node titles without rewriting the saved citation text. This display does not require Citar. Run =org-roam-organize-cite-display-refresh= after changing literature titles or managed tag membership; title caches are not automatically invalidated across buffers.
- Citar's basic Org Cite activation recognizes managed UUID keys through a temporary entry projection. Activation falls back to ordinary Citar behavior when that projection fails. Display refresh also respects buffers with Font Lock disabled.

** Source layout and Nix packaging
The package's Lisp files now live under =lisp/=. Manual installations must put
that directory on =load-path=; straight recipes must include =lisp/*.el=, as in
the configuration example below. Install all package modules together, rather
than copying only =org-roam-organize.el=.

The Nix flake uses the personal-nixpkgs framework and provides the named
=org-roam-organize= and =emacs= packages without a default package. Select a name
explicitly when building. Checks retain separate core, Citar, citation-export, and
citation-display suites, with package-lint and treefmt checks.

** Integration names
The source layout and citation integration namespaces have changed without
compatibility aliases.  The package entry point remains
=org-roam-organize.el=, so configurations that only use
=(require 'org-roam-organize)= and select integrations through the registry do
not need to load the new internal modules directly.

Configurations that explicitly load citation integration libraries must use
the new feature names:

#+begin_src emacs-lisp
  ;; Old names no longer provided:
  ;; (require 'org-roam-organize-citar)
  ;; (require 'org-roam-organize-biblatex)

  (require 'org-roam-organize-cite-citar)
#+end_src

All Citar adapter implementation symbols moved from the
=org-roam-organize-citar-= namespace to the internal
=org-roam-organize-cite-citar--= namespace.  In particular, the following old
names did not contain the conventional =--= marker but were adapter lifecycle
or callback implementation details and are now removed:

- =org-roam-organize-citar-setup=
- =org-roam-organize-citar-teardown=
- =org-roam-organize-citar-dwim=

They have no supported public replacements.  Remove direct calls, key bindings,
and =citar-at-point-function= assignments that name them; select the adapter
through =:backend citar= on the unique =:cite t= registry record instead.  The
mode installs and removes its Citar callback automatically.  Names briefly used
during development under the new prefix without an internal marker—
=org-roam-organize-cite-citar-setup=,
=org-roam-organize-cite-citar-teardown=, and
=org-roam-organize-cite-citar-dwim=—are likewise not provided.

The former =org-roam-organize-biblatex= library is no longer provided.
Remove explicit requires and direct compatibility-layer calls; configure
ordinary Org Cite export instead. Bibliography propagation is part of the
common citation integration, with output owned by the selected processor.

The reserved Citar notes-source symbol likewise changed from
=org-roam-organize-citar= to =org-roam-organize-cite-citar=.  Update any
configuration that refers to that source directly.  The Nix check attributes
=ert-citar= and =ert-biblatex= were replaced by =ert-cite-citar= and
=ert-cite-export=, respectively. The export suite covers standard Org Cite
equivalence with both basic and BibLaTeX processors.

The old files, features, and symbol aliases are intentionally absent.  The
new =core=, =capture=, =entry=, =moc=, and =cite= libraries are implementation
modules; normal user configuration should continue requiring only
=org-roam-organize=.

* Features
The package includes the following main features:

** 1. Node Management
- Check package configuration and runtime capabilities
- Display detailed check and sync diagnostics in a temporary report buffer
- Create directories declared by basic registry records; multiple basic records may share one directory
- Create managed nodes from registry-derived capture templates

** 2. Tag Processing
- Tag-based node counting and statistics
- Tag-based MOC membership synchronization

** 3. Citation Management
- Display managed literature UUID citation keys as node titles in Org buffers
- Synchronize citing-node entries for literature nodes
- Citation entry synchronization
- Maintain generated =#+ROAM_CITING_NODE= keyword entries

** 4. Statistical Functions
- Count nodes with specific tags

** 5. MOC Management
- Configure managed MOC records with =org-roam-organize-registry=
- Create one MOC file and missing CUSTOM_ID management headlines
- Open the top-level MOC declared by the =:moc t= registry record
- Sync MOC node entries using =#+ROAM_NODE= keywords

* Requirements
This package depends on the following:

- Emacs 30.1 or later
- Org 9.5 or later
- Org-roam 2.3.1 or later
- Citar when a citation record enables the optional Citar backend; 1.4.0 is the minimum tested version, and setup validates required runtime capabilities

* Configuration
Before using this package, you need to configure the following variables:

- =org-roam-organize-directory=: Root directory for org-roam-organize
- =org-roam-organize-registry=: Registry of managed records and their tags, paths, directories, inbox headlines, node path templates, and file head templates

The =org-roam-organize-directory= must be inside =org-roam-directory=.

Each registry record must declare =:name= and =:tag=. Basic records use =:basic t= and a relative =:directory=. Exactly one record must be marked with =:moc t= for the top-level MOC, and it must also be =:basic t=. At most one record may use =:cite t= to mark literature nodes for citation export, checking, and citing-node entry synchronization. That record may use =:backend citar= to install the optional Citar integration with default creation formatting, or a tagged specification of the form =:backend '(citar :title FORMAT :info PLIST)=. A missing or nil =:backend= installs no adapter; unsupported backend names are ignored with a warning. The core =:cite t= behavior does not depend on a backend. Setting =:bibliography t= on the citation record enables interactive full-library bibliography discovery and export-time propagation from cited nodes. A missing or nil value leaves bibliography handling entirely to Org, Citar, and user configuration, without disabling UUID-to-citekey export conversion. Non-basic records may also use =:directory= to create managed nodes in an existing kind directory. Only the MOC record may declare =:moc-id= and =:moc-path=. These are independent optional constraints: tag discovery always requires one level-0 file node, and every explicit ID/path must also match. Without =:moc-path=, =<directory>/<name>.org= is only the initial creation target; the uniquely tagged file may subsequently move within the organizing root. With =:moc-path=, its actual path is fixed by that declaration. An occupied ID or file path never triggers a fallback or overwrites another node. The MOC record's =:moc-title= supplies the file title. Other records use =:moc-title= (defaulting to the capitalized name) for their management headline title, and =:tag= for its =CUSTOM_ID=. A title mismatch is a preflight error; change the configuration or file explicitly. The optional =:inbox= defaults to =Inbox=; its MOC-region and Cite meanings are described below.

Every record's =:tag= must be a nonempty Org tag: letters, digits, =_=, =@=, =#= and =%= only. Spaces, colons, hyphens, control characters and structure-changing text are rejected before MOC edits. This also makes the tag safe as a literal =CUSTOM_ID= value.

All =:moc-title= values must be nonblank single lines without control characters. For non-MOC records, the generated headline must parse back to exactly the declared title as Org's =:raw-value=, without TODO, priority, COMMENT, trailing tag or special footnote-section semantics. For example, =Research :physics:= and =TODO Research= are not plain management titles under the usual TODO configuration. Validation uses Org's parser, including configured TODO keywords; missing regions are also checked in the target file/template's TODO context before insertion. Choose an explicit plain =:moc-title= if the name-derived title is reserved. The MOC record's file title is a file keyword rather than a management headline.

The MOC file title, management titles and CUSTOM_ID values, and the MOC's FILETAGS, are structural text and are captured literally, including legal percent signs or strings such as =${title}=. For example, a MOC =:moc-title= of =Navigation %t= remains that exact file title rather than expanding to a date. Other template properties and keywords retain their normal capture expansion.

When the Citar backend is active, Org-roam Organize registers and selects its own Citar notes source. Citar note lookup and opening use managed literature node UUIDs internally, while note creation uses the citation record's managed capture template. Citation insertion through =citar-insert-citation=, or through =org-cite-insert= while the Citar Org Cite processor is active, translates selected external citekeys to managed UUIDs. At a citation, the adapter translates UUIDs back to external citekeys before running Citar's default action. In a tagged backend specification, =:title= is a Citar format string and defaults to =${title}=; =:info= is a plist mapping user-chosen Org-roam capture info keywords to Citar format strings. The adapter evaluates these strings with the entry supplied by Citar and passes the resulting title and info to the managed capture. Citar controls which fields are present in that entry through settings including =citar-templates=, =citar-link-fields=, and =citar-additional-fields=. Successful creation automatically adds the selected external citekey as =ROAM_REFS=, saves the node, and updates the Org-roam database. The template therefore must not create its own =roam_refs= property. It remains responsible for writing the citation record's =:tag= through the =filetags= keyword; Citar note lookup and citekey-to-UUID translation only recognize level-0 nodes carrying that tag. If a node already exists for the citekey, creation reports an error that identifies the citation record by its =:name= instead of opening or modifying the node. Disabling =org-roam-organize-mode= removes the adapter source and restores the Citar notes source that was active before setup. An existing source with the reserved =org-roam-organize-cite-citar= name prevents adapter installation; malformed Citar options likewise disable only the optional backend. The core mode remains enabled in either case.

While =org-roam-organize-mode= is enabled and the citation record sets =:bibliography t=, the core citation integration extends Org Cite's bibliography discovery with bibliography files declared by managed literature nodes.  This behavior is independent of the optional =:backend=.  Add a =BIBLIOGRAPHY= property to a level-0 literature node to associate a file with that node:

#+begin_src org
  :PROPERTIES:
  :ID: aaaaaaaa-aaaa-4aaa-8aaa-aaaaaaaaaaaa
  :ROAM_REFS: @external-citekey
  :BIBLIOGRAPHY: reference.bib
  :END:
  ,#+title: Example Paper
  ,#+filetags: :ref:
#+end_src

Place the property drawer at the top of the literature file. The value is resolved relative to that file, using indexed =nodes.file= and =nodes.properties= from the Org-roam database. Saved metadata changes become visible after the corresponding database update. =BIBLIOGRAPHY= is an Org-roam Organize metadata convention, separate from Org Cite's =#+bibliography:= keyword.

Interactive Org Cite consumers such as Citar see the full collection of managed bibliography paths, deduplicated and sorted after existing bibliography configuration. During export, full-library expansion is suppressed before Org acquires its bibliography. The parse-tree filter translates managed UUIDs and adds only bibliography paths belonging to cited managed nodes after standard preprocessing and exclusion. Both the export environment and the ordinary discovery interface expose the resulting list for that export; normal interactive discovery resumes after success or failure.

Explicit =#+bibliography:= declarations and =org-cite-global-bibliography= retain their order and precedence, including explicitly supplied files that also belong to managed nodes. Additional managed paths are sorted and deduplicated. A node without =BIBLIOGRAPHY= may use those ordinary settings. With missing or nil =:bibliography=, users can maintain one bibliography centrally while retaining UUID citation conversion.

The package does not insert node properties, scan directories, read literature source files during export, or validate bibliography files for existence, readability or contents. It does not select a processor, citation style or bibliography style, repair backend-specific output, or insert =#+print_bibliography:=. Those remain ordinary Org Cite and document configuration. Restart =org-roam-organize-mode= after changing =:bibliography=.

The optional =:template= value is a structured alist for the generated managed capture template. Its optional =path= entry controls the ordinary node file path inside the =${id}/= bundle directory and defaults to =${slug}.org=. The =path= entry may contain bundle-internal subdirectories, is ignored by MOC capture, and cannot be declared by the =:moc t= record. Its =properties= section is emitted inside an Org property drawer. Its =keywords= section is emitted as Org file keywords. Entries are emitted in alist order. Repeated keys are emitted repeatedly. A nil value emits an empty property or keyword value. String values are written into the generated Org-roam capture template, so Org capture escapes such as =%<...>= and Org-roam placeholders such as =${field}= may be expanded by =org-roam-capture-=. The =filetags= keyword expects a string list and is formatted as Org file tags, for example =("zettel" "note")= becomes =:zettel:note:=. Other values are written directly as strings. When a record declares both =:tag= and a =filetags= entry in the =keywords= section, =filetags= must include the record tag.

MOC creation takes the file title, properties and keywords from the unique =:moc t= record. Its template must explicitly include legal, nonempty =filetags= containing the MOC tag, and must not declare =ID=. Ordinary record templates are used only for ordinary capture, never for MOC file heads or management headlines.

For a dynamic date, use Org capture's time escape syntax:

#+begin_src emacs-lisp
  :template '((path . "${slug}.org")
              (keywords . ((date . "%<%Y-%m-%d %A %H:%M:%S %z>"))))
#+end_src

The optional =:provider= value customizes data collection for ordinary managed node creation. When =:provider= is missing or nil, =org-roam-organize-node-create= uses the built-in provider, which reads a node title. A non-nil provider must be a function or function symbol. It is called with the full registry record:

#+begin_src emacs-lisp
  (funcall provider record)
#+end_src

The provider should return nil to cancel creation, or a request plist with a non-empty =:title= string and an optional =:info= plist:

#+begin_src emacs-lisp
  ( :title TITLE
    :info INFO)
#+end_src

The =:info= plist is passed to =org-roam-capture-= so placeholders such as =${author}= in =:template= values can be expanded. Providers only supply title and capture info; Org-roam-organize still controls paths, targets, and capture templates.

The old fixed directory and file-moving interface was removed in v0.4.0. This includes the former fleeting/permanent directory variables, move-related variables and aliases, and headline move/delete commands. The old =org-roam-organize-moc-update= command was also replaced by =org-roam-organize-moc-sync=.

* Usage
1. Configure the required variables in your Emacs configuration
2. Enable =org-roam-organize-mode= with =M-x org-roam-organize-mode= or your configured toggle key
3. Run =org-roam-organize-check-setup= to verify your configuration and runtime capabilities
4. After first-time setup or registry directory changes, run =org-roam-organize-create-directories= to create basic registry directories
5. Use =org-roam-organize-node-create= to create managed non-MOC nodes from registry records with =:directory=
6. After adding registry records, run =org-roam-organize-moc-create= to add missing management headlines to the unique MOC
7. Use =org-roam-organize-moc-sync= to sync MOC region entries
8. Use =org-roam-organize-cite-check= to check managed citation reference consistency
9. Use =org-roam-organize-cite-sync= to sync citing-node entries

Commands that produce detailed diagnostics use the =*Org-roam Organize Report*= buffer for the full report. Successful commands without warnings keep the interface quiet and only show a short minibuffer summary. Failed checks and sync commands with warnings display the report buffer and leave a short minibuffer notice pointing to it.

* Managed Node Creation
The command =org-roam-organize-node-create= creates ordinary managed Org-roam nodes from non-MOC registry records that declare =:directory=. It prompts for a registry record, asks that record's provider for a node creation request, then calls =org-roam-capture-= with a registry-derived template. The default provider prompts for a node title.

Managed node files use this target path template under =org-roam-organize-directory=:

#+begin_src text
  <directory>/${id}/${path}
#+end_src

When =path= is omitted from a record's =:template=, it defaults to =${slug}.org=, giving the standard path:

#+begin_src text
  <directory>/${id}/${slug}.org
#+end_src

During capture, Org-roam assigns the node ID. Org-roam-organize computes the expanded bundle root =<directory>/<id>/= in =org-roam-capture-preface-hook=, verifies the target file stays inside that bundle root, and creates the target file's parent directory before the file is opened. After capture, Org-roam-organize cleans only the bundle root: empty bundle roots are removed automatically, while non-empty aborted bundle roots require interactive confirmation before recursive deletion.

A minimal custom provider can supply dynamic fields for placeholders used by the record template when the user invokes =org-roam-organize-node-create=. Citar notes creation does not call this provider; the Citar adapter obtains the initial title from the bibliography entry and owns cite ref creation.

#+begin_src emacs-lisp
  (defun my-org-roam-organize-reading-provider (_record)
    (let ((title (read-string "Reading note title: "))
          (author (read-string "Author: ")))
      (unless (string= title "")
        (list :title title
              :info (list :author author)))))

  ;; Add to an otherwise valid registry that includes its :moc t record.
  (add-to-list
   'org-roam-organize-registry
   (list :name "reading"
         :tag "reading"
         :basic t
         :directory "reading"
         :provider #'my-org-roam-organize-reading-provider
         :template '((path . "note.org")
                     (keywords . ((author . "${author}")
                                  (date . "%<%Y-%m-%d %A %H:%M:%S %z>")
                                  (description . nil)
                                  (filetags . ("reading")))))))
#+end_src

* MOC Entry Format
Managed MOC node entries are stored as Org keywords:

#+begin_src org
  ,#+ROAM_NODE: [[id:node-id][Node title]]
#+end_src

Entries marked for future deletion workflows may use:

#+begin_src org
  ,#+ROAM_NODE: [[id:node-id][Node title]] :delete t
#+end_src

The unique MOC file has a file-level Org-roam ID and the MOC record's tag. Each non-MOC record owns one management headline with =CUSTOM_ID= equal to its tag and title equal to =:moc-title= (or the capitalized name). All management headlines must share a level, with different parents allowed. Duplicate CUSTOM_ID values, title mismatches, nesting or mixed levels are errors before editing. If a region is missing but a non-commented same-title headline carries an unregistered CUSTOM_ID (including an empty value), the identity is ambiguous: create and sync report a conflict for manual resolution rather than adopting it or creating a duplicate. Titles without CUSTOM_ID do not establish management identity, and manual children of known management regions are excluded from this ambiguity check. A valid known CUSTOM_ID takes precedence over unrelated same-title content; records may legitimately share a title while using distinct tags.

#+begin_src org
  :PROPERTIES:
  :ID: 7d713c24-20f2-467a-9a98-67a704ac31ec
  :END:
  ,#+title: Navigation
  ,#+filetags: :map:

  ,* Fleeting
  :PROPERTIES:
  :CUSTOM_ID: idea
  :END:
  ,** Inbox
  ,#+ROAM_NODE: [[id:idea-id][Idea title]]

  ,* Permanent
  :PROPERTIES:
  :CUSTOM_ID: zettel
  :END:
#+end_src

=moc-create= preserves the existing file head and handwritten contents, and adds only missing management headlines. New layouts default to level 1. Later additions inherit the existing common level L. At L=1, new management headlines always append at EOF. At L>1, the MOC record's =:inbox= names a level-1 container, independently of L. Org AST lookup identifies the non-commented level-1 Inbox and its subtree; missing regions are inserted before its first child headline, after its introductory text and properties. If it has no children, they append inside that Inbox. If it does not exist, create a level-1 Inbox at EOF and insert the regions there. The new management headlines retain level L, even when L>2: no intermediate levels are created, and existing regions are never moved. Multiple matching level-1 Inboxes are ambiguous and cause a preflight error. A newly created Inbox name must also be a plain single-line Org headline in the target syntax. Empty member Inboxes are not pre-created.

=moc-sync= only reconciles existing regions. Missing members are added under that record's direct child =:inbox= at level L+1, created inside its region when needed. Each region may have at most one non-commented matching direct-child Inbox. Sync checks this even when no members are missing; multiple matches in any valid region reject the entire sync before edits, saving or DB refresh. Deeper same-name headlines and matching Inboxes in other regions are independent and may repeat. A missing Inbox is created only when members need insertion. Entries are placed before the first Inbox child headline; when childless, they append after the Inbox's metadata and existing text, preserving property drawers, planning information and handwritten content. Existing valid entries throughout the region keep their relative positions, including entries in manual subsections. Titles are refreshed, stale entries removed, duplicates preserved/reported per region, and malformed entries reported without alteration. The same node may appear in different tag regions. COMMENT subtrees, source blocks, non-managed areas and headline nodes are excluded; only tagged level-0 nodes outside the MOC file are members.

The MOC document is parsed once for regional synchronization (individual entry values still use temporary Org buffers). Existing edits are applied globally from the end of the file; insertion markers track boundaries. A changed MOC is saved and its DB entry refreshed once; unchanged sync writes nothing. Missing regions can be reported while other valid regions synchronize. Identity or structural conflicts reject the whole operation. Cite continues to use its existing per-file level-1 Inbox behavior.

* Citation Entry Format
Generated citing-node entries for literature nodes are stored as Org keywords under the =:inbox= level-1 headline of each =:cite t= record node:

#+begin_src org
  ,#+ROAM_CITING_NODE: [[id:node-id][Node title]]
#+end_src

Managed citation references use the literature node UUID in the source Org text:

#+begin_src org
  [cite:@literature-node-uuid]
#+end_src

When =org-roam-organize-mode= is enabled, managed UUID keys are displayed as
their literature node titles in Org buffers.  This presentation is automatic
for the unique =:cite t= record and does not depend on the selected citation
backend.  It changes neither the saved citation text nor its Org Element key.
Ordinary citation keys and managed nodes without usable titles retain their
source display.  Run =org-roam-organize-cite-display-refresh= in an Org buffer
after changing a literature node title or its managed tag membership.

The corresponding literature node keeps its current external bibliography citekey in exactly one =refs.type = "cite"= =ROAM_REFS= entry:

#+begin_src org
  :ROAM_REFS: @external-citekey
#+end_src

With =:backend citar=, the adapter creates this property after a successful Citar note capture, so the citation record's capture template does not need to declare it. Literature nodes created through another path remain the user's responsibility and are reported by =org-roam-organize-cite-check= when the mapping is missing or ambiguous.

The command =org-roam-organize-cite-check= performs a global read-only check for the single =:cite t= registry record. It reports managed literature nodes that lack a cite-type ref, nodes that have more than one cite-type ref, and external citekeys attached to multiple managed literature nodes.

The command =org-roam-organize-cite-sync= performs a global sync for the same record. Before writing generated entries, it requires every managed literature node to have exactly one cite ref. It then computes citation relationships from Org-roam's =refs= and =citations= tables using =refs.node_id = citations.cite_key=, updates existing link titles, adds missing citing nodes, removes stale entries, and preserves duplicate entries while reporting them. Unlike the stricter global cite check, a citekey attached to multiple managed literature nodes remains a non-blocking sync warning.

When =org-roam-organize-mode= is enabled, export-time citation conversion is registered through Org export's parse-tree filter. During export, citation keys that match managed literature node UUIDs are replaced with the current external citekey from =refs.ref=. Export validation is limited to managed literature UUIDs that appear in the current export tree; unrelated literature node metadata does not block export. Citation keys that do not match managed literature nodes are left unchanged, and the source Org buffer is not modified.

* Reports
Detailed command diagnostics are written to the temporary buffer =*Org-roam Organize Report*=. The buffer is overwritten for each displayed report, uses =special-mode=, and is read-only. Report history is not retained.

The commands =org-roam-organize-check-variables=, =org-roam-organize-check-setup=, =org-roam-organize-moc-sync=, =org-roam-organize-cite-check=, and =org-roam-organize-cite-sync= use this buffer when they have detailed failures or warnings to show. Clean successful runs only print a short summary in the minibuffer.

* Implementation Details
The package uses Org-roam's database queries to resolve MOC nodes by file path, query level-0 nodes by tag, count managed nodes, map managed literature node UUIDs to external citekeys, and compute citing-node relationships. MOC and citation entry synchronization is implemented through shared id-link keyword helpers that parse real Org keyword elements with Org Element, update link descriptions with Org link formatting, preserve duplicate entries, remove stale entries, and insert missing entries under the configured level-1 inbox headline. Export-time citation conversion uses Org export's parse-tree filter and only rewrites citation-reference keys in the exported tree. It includes configuration validation, root directory validation, runtime capability validation, report-buffer display for detailed diagnostics, and short minibuffer notices for report-producing commands. Runtime capability validation checks the Org-roam capture interfaces, Org Element parsing and mutation functions, Org export filter hook, Org link formatting, Org capture finalize hook, and Seq helpers used by the current implementation.

The mode includes a startup hook that validates setup when the mode is enabled.

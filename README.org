* Overview
Org-roam-organize is an Emacs package for managing Org-roam Map of Contents (MOC) files and node references. It provides a minor mode with commands for checking setup, creating managed nodes, creating missing MOC files, syncing MOC entries from Org-roam node tags, and completing missing backlinks.

* Features
The package includes the following main features:

** 1. Node Management
- Check package configuration and runtime capabilities
- Create directories declared by basic registry records
- Create managed nodes from registry-derived capture templates

** 2. Tag Processing
- Tag-based node counting and statistics
- Tag-based MOC membership synchronization

** 3. Citation Management
- Synchronize citing-node entries for literature nodes
- Citation entry synchronization
- Maintain generated =#+ROAM_CITING_NODE= keyword entries

** 4. Statistical Functions
- Count nodes with specific tags
- Update managed tag and node count information in MOC files
- Maintain dynamic counters in properties

** 5. MOC Management
- Configure managed MOC records with =org-roam-organize-registry=
- Create missing MOC files from registry-derived paths and file heads
- Open the top-level MOC declared by the =:moc t= registry record
- Sync MOC node entries using =#+ROAM_NODE= keywords

* Configuration
Before using this package, you need to configure the following variables:

- =org-roam-organize-directory=: Root directory for org-roam-organize
- =org-roam-organize-registry=: Registry of managed records and their tags, paths, directories, inbox headlines, node path templates, and file head templates
- =org-roam-organize-moc-managed-tag-property=: Property to store managed tag
- =org-roam-organize-moc-managed-node-count-property=: Property to store node count

The =org-roam-organize-directory= must be inside =org-roam-directory=.

Each registry record must declare =:name= and =:tag=. Basic records use =:basic t= and a relative =:directory=. The top-level MOC record is marked with =:moc t= and must also be =:basic t=. At most one record may use =:cite t= to mark literature nodes for citing-node entry synchronization. Non-basic records may also use =:directory= to create managed nodes in an existing kind directory. MOC files use =:moc-path= and =:moc-title= when explicitly provided, or derive them from the record name and the =:moc t= directory when absent. The optional =:inbox= value names the level-1 headline used for newly added generated entries and defaults to =Inbox=.

The optional =:template= value is a structured alist for the generated managed capture template. Its optional =path= entry controls the ordinary node file path inside the =${id}/= bundle directory and defaults to =${slug}.org=. The =path= entry may contain bundle-internal subdirectories, is ignored by MOC capture, and cannot be declared by the =:moc t= record. Its =properties= section is emitted inside an Org property drawer. Its =keywords= section is emitted as Org file keywords. Entries are emitted in alist order. Repeated keys are emitted repeatedly. A nil value emits an empty property or keyword value. String values are written into the generated Org-roam capture template, so Org capture escapes such as =%<...>= and Org-roam placeholders such as =${field}= may be expanded by =org-roam-capture-=. The =filetags= keyword expects a string list and is formatted as Org file tags, for example =("zettel" "note")= becomes =:zettel:note:=. Other values are written directly as strings. When a record declares both =:tag= and a =filetags= entry in the =keywords= section, =filetags= must include the record tag.

For a dynamic date, use Org capture's time escape syntax:

#+BEGIN_SRC emacs-lisp
  :template '((path . "${slug}.org")
              (keywords . ((date . "%<%Y-%m-%d %A %H:%M:%S %z>"))))
#+END_SRC

The optional =:provider= value customizes data collection for ordinary managed node creation. When =:provider= is missing or nil, =org-roam-organize-node-create= uses the built-in provider, which reads a node title. A non-nil provider must be a function or function symbol. It is called with the full registry record:

#+BEGIN_SRC emacs-lisp
  (funcall provider record)
#+END_SRC

The provider should return nil to cancel creation, or a request plist with a non-empty =:title= string and an optional =:info= plist:

#+BEGIN_SRC emacs-lisp
  ( :title TITLE
    :info INFO)
#+END_SRC

The =:info= plist is passed to =org-roam-capture-= so placeholders such as =${author}= in =:template= values can be expanded. Providers only supply title and capture info; Org-roam-organize still controls paths, targets, and capture templates.

The old fixed directory and file-moving interface was removed in v0.4.0. This includes the former fleeting/permanent directory variables, move-related variables and aliases, and headline move/delete commands. The old =org-roam-organize-moc-update= command was also replaced by =org-roam-organize-moc-sync=.

* Usage
1. Configure the required variables in your Emacs configuration
2. Enable =org-roam-organize-mode= with =M-x org-roam-organize-mode= or your configured toggle key
3. Run =org-roam-organize-check-setup= to verify your configuration and runtime capabilities
4. After first-time setup or registry directory changes, run =org-roam-organize-create-directories= to create basic registry directories
5. Use =org-roam-organize-node-create= to create managed non-MOC nodes from registry records with =:directory=
6. After adding new registry records, run =org-roam-organize-moc-create= to create missing MOC files
7. Use =org-roam-organize-moc-sync= to sync MOC entries and managed information
8. Use =org-roam-organize-cite-sync= to sync citing-node entries

* Managed Node Creation
The command =org-roam-organize-node-create= creates ordinary managed Org-roam nodes from non-MOC registry records that declare =:directory=. It prompts for a registry record, asks that record's provider for a node creation request, then calls =org-roam-capture-= with a registry-derived template. The default provider prompts for a node title.

Managed node files use this target path template under =org-roam-organize-directory=:

#+BEGIN_SRC text
  <directory>/${id}/${path}
#+END_SRC

When =path= is omitted from a record's =:template=, it defaults to =${slug}.org=, giving the standard path:

#+BEGIN_SRC text
  <directory>/${id}/${slug}.org
#+END_SRC

During capture, Org-roam assigns the node ID. Org-roam-organize computes the expanded bundle root =<directory>/<id>/= in =org-roam-capture-preface-hook=, verifies the target file stays inside that bundle root, and creates the target file's parent directory before the file is opened. After capture, Org-roam-organize cleans only the bundle root: empty bundle roots are removed automatically, while non-empty aborted bundle roots require interactive confirmation before recursive deletion.

A minimal custom provider can supply dynamic fields for placeholders used by the record template:

#+BEGIN_SRC emacs-lisp
  (defun my-org-roam-organize-literature-provider (_record)
    (let ((title (read-string "Literature title: "))
          (author (read-string "Author: "))
          (citekey (read-string "Citation key: ")))
      (unless (string= title "")
        (list :title title
              :info (list :author author
                          :citar-key citekey)))))

  (setq org-roam-organize-registry
        (list (list :name "literature"
                    :tag "ref"
                    :basic t
                    :cite t
                    :directory "literature"
                    :provider #'my-org-roam-organize-literature-provider
                    :template '((path . "${citar-key}.org")
                                (properties . ((roam_refs . "@${citar-key}")))
                                (keywords . ((author . "${author}")
                                             (date . "%<%Y-%m-%d %A %H:%M:%S %z>")
                                             (description . nil)
                                             (filetags . ("ref"))))))))
#+END_SRC

* MOC Entry Format
Managed MOC node entries are stored as Org keywords:

#+BEGIN_SRC org
  #+ROAM_NODE: [[id:node-id][Node title]]
#+END_SRC

Entries marked for future deletion workflows may use:

#+BEGIN_SRC org
  #+ROAM_NODE: [[id:node-id][Node title]] :delete t
#+END_SRC

During sync, existing valid entries keep their position and order. Missing nodes are added under the configured level-1 inbox headline. Entries whose target node no longer exists or no longer has the managed tag are removed. Duplicate entries are preserved, synchronized, and reported.

* Citation Entry Format
Generated citing-node entries for literature nodes are stored as Org keywords under the =:inbox= level-1 headline of each =:cite t= record node:

#+BEGIN_SRC org
  #+ROAM_CITING_NODE: [[id:node-id][Node title]]
#+END_SRC

The command =org-roam-organize-cite-sync= performs a global sync for the single =:cite t= registry record. It computes citation relationships from Org-roam's =refs= and =citations= tables, uses naked cite keys in the database query, updates existing link titles, adds missing citing nodes, removes stale entries, and preserves duplicate entries while reporting them.

* Implementation Details
The package uses Org-roam's database queries to resolve MOC nodes by file path, query level-0 nodes by tag, count managed nodes, and compute citing-node relationships. MOC and citation entry synchronization is implemented through shared id-link keyword helpers that parse real Org keyword elements with Org Element, update link descriptions with Org link formatting, preserve duplicate entries, remove stale entries, and insert missing entries under the configured level-1 inbox headline. It includes configuration validation, root directory validation, runtime capability validation, and warning messages for common setup problems. Runtime capability validation checks the Org-roam capture interfaces, Org Element parsing functions, Org link formatting, Org capture finalize hook, and Seq helpers used by the current implementation.

The mode includes a startup hook that validates setup when the mode is enabled.
